## Checkpoint: 15 November 2026

The authorized release workflow is `main` in [`devoralabsapp/lessonbrook`](https://github.com/devoralabsapp/lessonbrook) to the existing Vercel project. Verify the production alias against the exact pushed commit when handing off a release. Use the current task and branch to decide what to work on next.

- **iOS 0.5.1, build 19 — restored workspace layout**. The maintainer confirmed the SwiftUI version is faster and requested the former layout back. SwiftUI now reproduces the existing web directory cards, visible filters, icon List/Notes/Month controls, pastel paper, framed student/class identities, direct Edit/Archive actions, lesson date badges and statement metadata/payment placement. Native theme-aware form/checkbox/date/select/button components replace the grouped iOS Form/List presentation. The original Nunito font and OFL license are bundled locally. A custom themed header and the bottom tab inset reserve real content space. Editors retain the original framed hierarchy; the recipient preview keeps its own light palette. All screens remain SwiftUI and the RAM cache and per-tab stacks are retained. See `WorkspaceDesign.swift` and the architecture guide before extending these styles.

- **Selector refresh race**. Student selection and class-filter loading now follow `store.revision`. A foreground snapshot update can invalidate an inflight page read; the selector restarts with the new revision rather than displaying a cancelled request and an empty list. The native student → lesson → statement → cash-payment UI flow reproduces this path across the foreground timer.

- **iOS 0.5.0, build 18 — SwiftUI migration**. The iOS entry point, all five tabs, details, editors, month calendars, statement/payment/share tools, themes, settings, export and account deletion now use SwiftUI. `BrowserViewController` and the custom UIKit scene were removed. Android is unchanged. The app continues to call the existing authenticated Node APIs; no business logic or Firebase database access moved onto the phone. The Google SDK still needs its small UIKit presenter bridge for authentication. Web deployment does not update these new native screens: install the rebuilt iOS app.

- **Native state and caching**. `WorkspaceStore` owns separate tab navigation, session phase, foreground refresh, fictional demo replay, stable retry keys and bounded RAM directory pages. The HttpOnly session value is stored in device-only Keychain. No tuition data is persisted. Writes invalidate native pages after server success; external payment changes refresh through the existing server snapshot and statement checks. Native queries use Vietnam dates and preserve integer VND. Student selectors merge active and archived pages when needed, rather than treating the archived-only endpoint as the full student list.

- **Native validation checkpoint**. The Swift tests cover API cookies/CSRF/idempotency, directory invalidation, date boundaries, payload decoding and exact VietQR parity. A loopback-only native HTTP integration suite exercises Auth/Firestore Emulators with fictional accounts through class attendance, issuing/sharing, partial cash, payment edits/removal, settlement and account isolation. Native demo UI tests cover all six themes in Vietnamese and the English student/lesson/statement/payment flow and assert zero embedded WebViews. See the verification section for final results. Real Google authorization, delivery to Gmail, device installation and comparative physical-device performance remain separate checks. Do not infer a phone speed improvement from Simulator/XCTest timings.

- **Mobile month calendars**. Classes and Lessons now show the same colored event previews as desktop in their shared month grid. On narrow screens the time sits above the title, the grid keeps seven columns, and selecting a day opens its full agenda. The existing native apps load both tabs from the website and receive this update through deployment.

- **Mobile 0.4.11**. Native login shows the primary Google action, demo entry and language menu in a compact Retro layout. The mobile browser handoff uses a matching card. The signed-in native Dashboard follows the mobile demo's heading, summary labels, amount formatting and Upcoming lessons row styling while retaining its workspace snapshot and refresh behavior. The ignored mobile builds directory contains iOS build 17 and Android debug code 16. The iOS Simulator fixture covered English sign-in, Vietnamese expired sign-in and the Dashboard in Playful Retro and Afterhours.

- **Mobile 0.4.10**. Upcoming lessons on the native and mobile demo Dashboards uses the Student list layout, with a framed initial and lesson details in each tinted row. Today, This month, Clear filters and Select share the action row in Lessons. Signed iOS build 16 and Android debug code 15 are packaged in the ignored mobile builds directory. Dashboard rendering passed on iOS Simulator with English Playful Retro and Vietnamese Afterhours.

- **Statement cancellation and sharing**. The Cancel statement action is available near Edit statement if the server confirms that Payment history is empty. Cancelling revokes the link and releases the billed lessons. Settling the balance by cash, Shortcut transfer or payment edit revokes the share inside the payment transaction. Public reads also reject previously settled statements. Voided payments remain in history, and undoing a payment does not reactivate a revoked link.

- **Partial cash and the emailed VietQR**. After a partial cash payment is committed, the authenticated API schedules a Gmail follow-up for a statement with an active, previously emailed share and the same recipient. The follow-up QR carries the remaining balance and original transfer reference. Its link expires with the parent share. Unit tests check the exact QR image and send deduplication with mocked Gmail. Real mailbox delivery remains a separate check.

- **Mobile 0.4.9**. The Dashboard shows the outstanding amount as plain text and places Upcoming lessons below Active students. The mobile demo uses its own Dashboard layout and the existing demo summary and schedule APIs. iOS uses five UIKit buttons below the content view with theme colors and a safe-area inset. Android uses matching themed selection. Embedded pages leave 12 px between the end of the content and the bottom bar. The red note pin uses a contact shadow beneath its base.

- **Workspace cache**. Authenticated directory, lesson, statement, payment, summary and preference reads use a bounded 45-second server memory cache. Every request still checks session revocation and current account controls. A Firestore revision document supplies dependency-specific keys; business writes advance the affected revisions in the same transaction. The next read refills from Firestore, including after Shortcut payments, shared-link creation and scheduled lesson materialization. See `src/lib/server/workspace-cache.ts` and the architecture guide before adding another mutation. Cache storage is per warm server instance; direct Admin edits outside this contract may take up to the TTL to appear. No service, dependency or environment variable was added.

- **Smoothness and mobile reuse**. The server cache already serves mobile. The client now coalesces overlapping GETs only while pending, clears that registry around mutations, and still sends later reads to the server. Classes/Statements retain rows during revalidation of the same filter; changing filters hides the old result. Notes animate only in view while the document is visible, pivot around their pin, and use smaller hover/focus transforms. Red pushpins are shaded SVGs with metal needles and an embedded shadow. iOS/Android reuse their RAM Dashboard view and scroll position for equal validated snapshots, including theme/locale in the rendered state; sign-out and demo entry clear that memory. No persistent offline tuition cache was added.

- **Students and Classes**. Notes open by default. Names are larger and bold in both Notes and List. The name frame has a 2px border in the theme's primary color. In Notes, the name frame keeps the stronger paper color and the paper outside it is muted. The red pin, motion preferences, and underlined Edit/Archive actions remain part of the Notes design.
- **Lessons**. `/app/sessions` is the Lessons tab. Opening it from the navigation filters to this month in Vietnam time. Clear filters opens the full history, and student ledgers and explicit dashboard billing links start without a date restriction. Notes fill each complete grid row, keep the content centered, and render `No charge` as a status badge. The list supports automatic filtering, bulk completion of planned lessons and a month calendar.
- **Statements**. Uses the same directory card as Students, Classes and Lessons: the title and List/Notes buttons are in the header above the filters. List mode has compact rows separated by lines, with the amount and status on the right. Notes keep their pinned paper appearance inside the card. Opens on this month for the main tab and on all dates for direct student or status links. The date filter uses issue date, falling back to the Vietnam date of creation. `All time` restores the full history. Payment status sits beneath the amount in Notes. Cash payments and matched transfers appear in editable payment history.
- **Demo and mobile**. `/demo` uses fictional data scoped to its tab. iOS 0.5.0 uses the same fictional command handler through native SwiftUI screens. Android retains the embedded workspace. iOS UI changes require rebuilding/installing, while Android ledger screens continue to receive web deployments.

For note motion, start with [note-motion.ts](src/lib/note-motion.ts), `NotePin` in [record-note.tsx](src/components/record-note.tsx), and the note rules in [globals.css](src/app/globals.css). The `.record-note:has(> .record-identity)` selector confines the lighter paper treatment to student and class notes. The dark Afterhours FM theme has its own tint strengths. Statements layout lives in [list.tsx](src/features/statements/list.tsx).

## Resume work

1. Start from the current worktree. Keep unrelated changes and check for instructions in the directories you edit. Match Node 24, Java 21 for the emulators, and the pinned dependencies in the lockfile. Use `npm ci` when dependencies need installing.
2. For a layout or filter change, reproduce it with `/demo/students`, `/demo/classes`, `/demo/sessions`, or `/demo/statements`. Check the actual list mode and theme named in the request. For shared styles, check Notes and List, narrow and wide screens, English and Vietnamese, and a dark theme. Use the Auth/Firestore Emulator for account-owned flows.
3. Use a clean checkout with demo configuration for local testing if the working copy contains hosted settings. See [local setup](README.md#quick-start). Preserve the loopback origin `http://localhost:3000` and stop only processes you started. Install the browser once with `npx playwright install chromium` if it is missing.
4. Run `npm run check` for lint, types, unit tests and the build, then `npm run test:emulator` for backend, Rules and browser checks. The test runner starts its own app and emulators. If a port is occupied, identify its owner before resolving the conflict. Keep browser traces, emulator data, local configuration and credentials out of commits.
5. In the maintainer workflow, authorized pushes to `main` trigger the linked Vercel production build. For forks or external contributions, follow [CONTRIBUTING.md](CONTRIBUTING.md). Verify the deployment for the intended commit and its production domain before reporting it live. Run `npm run check:public -- https://your-app.example` with the configured origin for read-only smoke checks. Follow [Deployment](docs/DEPLOYMENT.md) for hosting or environment changes.

For existing regression examples, start with [Notes](tests/e2e/notes.spec.ts), [calendars](tests/e2e/calendar.spec.ts), [locale and demo](tests/e2e/i18n.spec.ts), [mobile layouts](tests/e2e/mobile-layout.spec.ts), and [payments and sharing](tests/e2e/payments-sharing.spec.ts).
